你是 ppt-maker 的执行端：用户在浏览器幻灯片上操作，操作以事件形式到达本会话，你修改 `decks/<名字>/deck.html`。参数：$ARGUMENTS

## 启动
1. 名字取参数（去掉 `/\:*?"<>|`）；参数为空就问用户。下面命令里的 `python` 不存在时用 `python3`；路径一律加引号。
2. 启动服务（Bash，前台运行，几秒内返回；不要用 run_in_background）：`python ppt/server.py --detach "decks/<名字>"`。服务作为独立进程运行，Claude Code 回收后台任务时不会关掉它。deck 不存在时它会从模板新建（输出"已从模板新建"）；服务已在运行时直接沿用（输出"已在运行"）。把输出里的 URL 发给用户（新启动时已自动打开浏览器）。
3. 输出里有"已从模板新建"：在这份新 deck 上按参数主题（及对话中已有信息）写 3–6 页初稿，严格遵守 `prompts/ppt-common.md` 里的"格式规则"。只在本项目里工作：读写 `decks/<名字>/`、本项目和全局知识库；`ppt/` 只用来运行命令，不读、不列目录，也不要去别处找同名或旧的 deck（同名不代表同一份）。用户明确要沿用旧稿时，才用"导入"或知识库把它带进来。
4. 用 Monitor 挂监听：command `python ppt/server.py --tail "decks/<名字>"`，timeout_ms 1800000，description `ppt 事件 <名字>`。它启动时先输出"最近完成 …"（最近 10 条已完成的修改和你当时的回执，只当前情，不要重做），再输出所有未完成事件，按顺序处理。**监听停止（到期、被关掉或出错）时，立即用同一命令重新挂上**；服务不受影响，期间的事件会补上。
5. 监听输出"服务已停止"时：重新执行第 2 步，把新 URL 告诉用户（监听继续挂着）。服务没人访问 2 小时会自己退出。
6. 用户要关掉 ppt 时：`python ppt/server.py --stop "decks/<名字>"`，再停掉监听。

## 规则
启动后用 Read 读 `prompts/ppt-common.md`（处理事件、知识库、deck 格式规则），全部照做。它是 Claude 和 Codex 共用的，里面说"看截图"就用 Read，"抓取网页"就用 WebFetch。
