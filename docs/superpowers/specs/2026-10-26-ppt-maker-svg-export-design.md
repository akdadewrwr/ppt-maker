# ppt-maker 子项目：SVG 插图导出为可编辑形状 — 设计

## 为什么
项目的目标是"导出能在 PowerPoint 里继续编辑的 pptx"。用户真实使用中，5 条意图里有 3 条是"加插图"，agent 按规则用内联 SVG 画（`prompts/ppt-common.md` 规则 5）。但 `ppt/export.js:7` 的 `RASTER_TAGS` 把所有 `<svg>` 一律转成图片，导出后插图里的字、颜色、位置都改不了。

## 用户要的（原话归纳）
- 在 PowerPoint 里能改：**插图里的文字**、**形状的颜色**、**形状的大小和位置**。
- 形状本身的轮廓"改动很少"——不需要能逐点编辑路径。
- 插图里有一小块转不了时：**只把那一小块转成图片，其余照样能编辑**（不是整张退回图片）。

## 目标
- 每个块里的内联 `<svg>`（插图、`data-kind="icon"` 图标、`data-kind="ink"` 笔迹）导出成一个 PowerPoint **组合**，组合里每个 SVG 元素是一个原生对象。
- 导出后看起来和页面上一致：★ 指生成的 pptx 里的坐标、尺寸与浏览器量到的相差 ≤ 1px、颜色值相同（自动测试检查这个）；PowerPoint 实际渲染因字体可用性产生的差异不另做校准。
- 导出报告照常列出转成图片的部分和原因，粒度到单个元素。

## 非目标
- 不改页面编辑、`deck.html` 格式、agent 规则；只改导出。
- 不做 pptx 导入时把形状转回 SVG。
- 不做动画。
- 不追求路径在 PowerPoint 里可逐点编辑的"漂亮"控制点；能改颜色、大小、位置即可。
- `.obj` 形状和箭头（`data-kind="shape"/"arrow"`）已经是原生对象，不动。

## 反目标（技术上能用但算失败）
- 导出后插图跑位、文字换行错乱、颜色和页面不同。
- 因为一个不支持的元素导致整张插图变成图片。
- 某张插图转换出错导致整页或整份导出失败（现有"一项失败不拖垮整份"的原则要保持）。

## 元素对应（★ 为设计者的决定）
在浏览器端（`export.js`）用计算后的样式和 `getScreenCTM()` 把每个元素换算成页面坐标（宽 1280 画布），主题变量 `var(--x)` 因此自然变成真实颜色。

| SVG | PowerPoint |
|---|---|
| `rect`（含 `rx/ry`） | 矩形 / 圆角矩形，圆角按比例设 adj |
| `circle`、`ellipse` | 椭圆 |
| `line`、`polyline` | 线条；`polyline` 和不闭合的路径用任意多边形（无填充） |
| `polygon`、`path` | 任意多边形（freeform）；曲线要保留成曲线或足够细的折线，视觉一致即可；多个子路径（含镂空）要保留 |
| `text`（含 `tspan`） | 文本框，无边框、无填充、不自动换行；字号、字体、颜色、粗体/斜体、`text-anchor` 对齐保留；文字位置以页面上量到的外框为准 |
| `marker-start/end`（箭头） | 线条自带的箭头端（PowerPoint `headEnd/tailEnd`）；★ 任何 marker 都当作三角箭头；**用户决定：箭头颜色跟线同色**（marker 自己的填充色不同时也一样，这是允许的差异，不算"颜色不一致"），这样在 PowerPoint 里改线色时箭头一起变；★ 大小取 sm/med/lg 中最接近的 |
| `g` | ★ 不单独生成对象，展开成子元素（整张 SVG 只有一层组合） |

样式：`fill`、`stroke`、`stroke-width`（按缩放换算）、`fill-opacity`/`stroke-opacity`/`opacity`（相乘后作为透明度）、`stroke-dasharray`（★ 映射到最接近的 PowerPoint 虚线预设）、`fill:none`/`stroke:none`。

变换：平移、缩放、旋转都能换算；★ 斜切（skew）或非等比缩放下的圆角这类无法如实表达的形状，该元素转图片。★ 文字例外：非等比缩放（如被拉伸的笔迹，`preserveAspectRatio="none"`）下的 `<text>` 仍导出为可编辑文本框，按页面上量到的外框和纵向字号放置——改字优先于像素一致。

## 转成图片的部分（只限那一个元素）
以下元素单独转成图片，放在组合里原来的层次位置，报告写明原因：
- 填充或描边用了 `url(#…)`（渐变、图案）
- 用了 `filter`、`clip-path`、`mask`
- `<image>`、`<foreignObject>`、`<use>`、`<textPath>`、`<pattern>` 等其他元素
- 换算或测量时出错（沿用现有"测量出错 → 转图片"的做法）

转图片沿用现有 `raster()` + `cut()` 机制（只显示被标记元素、整页渲染后裁切），它对 SVG 子元素同样适用。

★ 整张 SVG 里一个可转换的元素都没有时，像现在一样整张转一张图片。
★ `defs`、`marker`、`title`、`desc` 等不可见元素直接跳过。
★ 叠放顺序与 SVG 文档顺序一致。

## 导出端（`exporter.py`）
- 新增 item 类型（如 `k: 'group'`，带 `items` 子列表）；python-pptx 的组合对象有和页面一样的 `shapes` 接口，子元素复用现有的 `add_*` 函数加进组合。
- 新增任意多边形和箭头端的生成；现有矩形、椭圆、线条、文本框、图片的生成尽量复用。
- 报告：组合里的子元素按种类计入现有计数（文本框、形状、图片），转图片的子元素进入 `raster` 列表。
- 一个子元素生成失败：只跳过它并记入 `skipped`，组合其余部分保留。

## 约束
- 不加新依赖：浏览器端只用标准 DOM/SVG API；Python 端只用已有的 python-pptx。
- 生成的 XML 要能被 PowerPoint 直接打开、不弹"修复"提示（元素顺序遵守 schema，参考已有 `test_table_border_xml_is_in_schema_order` 的做法）。
- TDD：先写失败的测试再实现。
- 测试不碰 `decks/试用` 和用户真实的 `~/.ppt-maker`。

## 怎么算做成
- Python 测试：给定组合 item，生成的 pptx 里有一个组合，内含对应数量的原生形状/文本框/图片，颜色、位置、透明度、箭头端正确，XML 通过 schema 顺序检查。
- 端到端测试（`tests/e2e.mjs`）：一页含有矩形、圆、带箭头的线、路径、文字、一个带渐变的元素的 SVG 插图，导出后组合里各元素齐全，只有渐变那一个是图片，报告列出它。
- 用 `decks/试用` 的副本（复制到临时目录，不动原稿）导出一次，交给用户用 PowerPoint 打开：不报修复，插图可改字和颜色（★ 这一步由用户人工完成；因此 schema 顺序测试要覆盖组合、任意多边形 `custGeom`、`headEnd/tailEnd`、透明度）。

## 实现者可自行决定（审阅时已确认不必问）
报告里子元素的标签（SVG 子元素通常没有 id，可用"所在块 id + 元素类型 + 序号"）；父元素有阴影/变形/背景图时整张 SVG 仍像现在一样转图片；线端和拐角样式；`vector-effect="non-scaling-stroke"`；SVG 溢出隐藏时的裁切；只有一个子元素的组合。

## 留给实现者决定
- 路径命令（含弧线 `A`）的解析与转换方式，曲线用贝塞尔还是细分折线。
- 任意多边形用 python-pptx 的 freeform 构造器还是直接写 `custGeom` XML。
- 新 item 的具体字段名。
- 文本框内边距、基线到外框的换算细节（以导出后和页面对齐为准）。
